# V1

## Product listing filters (search/price/rating/discount/stock) built (2026-08-27)
Extended GET api/v1/products (index) with query filters, validated by new App\Http\Requests\Api\V1\ListProductsRequest: `search` (LIKE on name OR code), `min_price`/`max_price` (against the raw `unit_price` column, not the post-discount `final_price` — kept simple/portable; `max_price` has a `gte:min_price` rule), `rating` (minimum average rating from ReviewStatus::Approved reviews only), `discounted` (bool, true/false both filter now — previously only `discounted=1` did anything, `0`/absent were treated the same), `in_stock` (bool, true/false both filter on `current_stock`). ProductResource gained `average_rating` (rounded to 1 decimal, null if no approved reviews), populated via `withAvg` in index() and `loadAvg` in show() for consistency.

Gotcha (cost real debugging time): the `rating` filter cannot use `withAvg(...)->having('average_rating', ...)` — SQLite throws "HAVING clause on a non-aggregate query" because withAvg's per-row average is a scalar subquery, not a true GROUP BY aggregate, and SQLite (unlike MySQL) requires HAVING to reference a real aggregate. Used a correlated `whereRaw` subquery instead: `(select avg(rating) from reviews where reviews.product_id = products.id and reviews.status = ?) >= CAST(? AS REAL)`. The `CAST(? AS REAL)` is NOT optional — binding a plain PHP float (e.g. `4.0`) without it silently matches zero rows on SQLite, because a bound float gets sent with no column affinity to anchor it, and SQLite's storage-class comparison ranks TEXT above REAL, so the float-as-text binding compares as "greater than" any real avg() result regardless of numeric value. `unit_price >= ?` (min_price/max_price) doesn't need this cast because `unit_price` is a real table column with NUMERIC affinity, which SQLite applies to the bound parameter automatically — the bug only bites when comparing against a bare expression/subquery with no column affinity. Verified via `DB_CONNECTION=sqlite DB_DATABASE=:memory: php artisan tinker`. Don't rebuild — extend ProductController/ListProductsRequest instead, and keep the CAST if touching the rating filter again.
