# Notifications

## Forgot/reset password API built (2026-08-27) — email via Mail, phone via PlasGate
Built POST api/v1/auth/forgot-password and POST api/v1/auth/reset-password (guest, throttle:password-reset-request 5/min and throttle:password-reset 10/min by IP). Caller sends either `email` or `phone` (required_without each other). New table customer_password_resets (customer_id FK cascadeOnDelete, channel 'email'|'phone', code — Hash::make()'d 6-digit OTP, expires_at, used_at nullable) via App\Models\PasswordResetCode — note the model's table name does NOT match its pluralized class name (would resolve to password_reset_codes), so it sets `protected $table = 'customer_password_resets'` explicitly, same gotcha as [[models]]'s uncountable-noun note. Customer::passwordResetCodes() hasMany added; Customer model now `use Notifiable` (added specifically for this feature — wasn't there before) so `$customer->notify()` works, default mail routing uses its `email` column, no override needed.

App\Actions\Customers\SendPasswordResetCodeAction: deletes the customer's existing unused codes, creates one new row (Hash::make'd, 10-min expiry) inside DB::transaction, then dispatches App\Notifications\CustomerPasswordResetCode OUTSIDE the transaction (notification is ShouldQueue, queue is 'database' with after_commit=false — dispatching after commit avoids a queued job racing a not-yet-committed row). The notification's via() branches on channel like App\Notifications\NewOrderPlaced does: ['mail'] for email, [App\Notifications\Channels\PlasGateChannel::class] for phone — PlasGateChannel is a new custom channel mirroring the existing App\Notifications\Channels\TelegramChannel pattern exactly (plain send(object,Notification) class, Http::post with retry/timeout, reads $notifiable->phone directly, config in config/services.php `plasgate` block: base_url/private_key/secret_key/sender, env PLASGATE_*). The PlasGate base_url/payload shape (private_key + secret_key headers, {sender,to,content} body) was written from general knowledge of PlasGate's OTP API, NOT verified against live docs or a real account — confirm against PlasGate's actual API reference before going live, credentials are blank in .env/.env.example.

App\Actions\Customers\ResetCustomerPasswordAction validates the code via Hash::check against the customer's latest unused, unexpired row, marks it used_at, updates password (Customer casts password => 'hashed', so plain-text in is fine), and revokes ALL the customer's Sanctum tokens (`$customer->tokens()->delete()`) — forces re-login everywhere after a password reset, per laravel-security guidance.

Deliberate anti-enumeration behavior: forgot-password ALWAYS returns the same generic "if an account matches..." message whether or not the email/phone exists (silently no-ops instead of sending, no validation error) — do not add an `exists:customers` rule to ForgotPasswordRequest, it would leak account existence. reset-password treats "customer not found" and "wrong/expired code" identically (both throw a `code` validation error) for the same reason — do not surface which case occurred. Don't rebuild — extend SendPasswordResetCodeAction/ResetCustomerPasswordAction/AuthController instead.
